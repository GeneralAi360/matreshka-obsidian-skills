## Когда использовать

Создавать `.canvas`, когда пространственное расположение, группы и направленные связи важнее линейного текста. Для канонических определений, процессов и списков по умолчанию использовать Markdown, Mermaid или Base.

Canvas является представлением, а не канонической Wiki-страницей.

## Формат

Верхний JSON-объект содержит массивы `nodes` и `edges`.

Поддерживаемые node types:

- `text`;
- `file`;
- `link`;
- `group`.

Каждый node имеет уникальный `id`, координаты `x`, `y`, размеры `width`, `height` и соответствующее типу поле.

Edge имеет собственный `id`, `fromNode`, `toNode` и при необходимости стороны, endpoints, цвет и label.

Минимальный пример:

```json
{
  "nodes": [
    {
      "id": "source-layer",
      "type": "text",
      "text": "Sources",
      "x": 0,
      "y": 0,
      "width": 240,
      "height": 100
    },
    {
      "id": "wiki-layer",
      "type": "file",
      "file": "30_Wiki/Wiki-Index.md",
      "x": 360,
      "y": 0,
      "width": 300,
      "height": 180
    }
  ],
  "edges": [
    {
      "id": "sources-to-wiki",
      "fromNode": "source-layer",
      "toNode": "wiki-layer",
      "toEnd": "arrow"
    }
  ]
}
```

## Правила создания

1. Выбрать короткие стабильные node IDs.
2. Проверить уникальность node и edge IDs.
3. Использовать vault-relative paths для file nodes.
4. Проверить, что каждый edge ссылается на существующие nodes.
5. Размещать nodes без наложения и чрезмерного пустого пространства.
6. Использовать группы только для реальной смысловой области.
7. Не копировать полную заметку в text node, если можно сослаться на file node.

## Безопасность и проверка

- Снять baseline существующего Canvas.
- Не пересоздавать Canvas целиком ради одного node.
- Не удалять неизвестные nodes или edges как «лишние».
- Не менять ID существующего node без обновления всех edges.
- Не считать отсутствие node разрешением удалить соответствующий файл.
- Проверить JSON parser и открыть Canvas в Obsidian.
