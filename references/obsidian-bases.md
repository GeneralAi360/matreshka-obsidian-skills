## Назначение

Base является представлением над файлами и properties. Не использовать `.base` как второй источник истины и не переносить в него смысл, который должен находиться в Markdown или Schema.

Создавать Base, когда нужен повторяемый фильтр, сортировка, группировка, вычисляемое поле или табличный обзор. Для статического объяснения использовать Markdown Map.

## Порядок создания

1. Прочитать `01_System/Schema/properties.md`.
2. Проверить реальные имена и типы properties в существующих заметках.
3. Определить scope минимальным filter.
4. Добавить formulas только для производных значений.
5. Определить views, columns, sorting и grouping.
6. Проверить результат на реальном vault.

Минимальный пример:

```yaml
filters:
  and:
    - 'type == "concept"'
    - 'status != "archived"'
formulas:
  needs_review: 'review_due && review_due < today()'
views:
  - type: table
    name: Active concepts
    order:
      - file.name
      - status
      - review_due
      - formula.needs_review
```

Синтаксис и доступные функции сверять с текущей официальной документацией, а не угадывать.

## Безопасность

- Не переименовывать property ради Base без Schema migration.
- Не делать Base единственным местом, где виден статус или решение.
- Не использовать broad filter, который случайно включает `99_Private`.
- Не добавлять write workflow только из-за того, что Base показывает строку.
- Не удалять заметки, не попавшие в фильтр.
- Не менять существующие `.base` целиком при добавлении одного view.

## Проверка

1. Файл является валидным YAML.
2. Filters используют существующие поля.
3. Formulas ссылаются на правильные типы данных.
4. Private и project-scoped материалы не попали в общий обзор.
5. Порядок колонок объясним пользователю.
6. Base открывается в установленной версии Obsidian.
